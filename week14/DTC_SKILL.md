# Inquiry-dtc 车载故障码诊断查询

面向 Agent 的纯推理查询类 Skill：用户输入 DTC 故障码，Agent 从车载 DTC 知识库检索匹配条目，**自动生成 HTML 诊断报告**（故障解释、可能诱因、排查步骤、维修建议），并在浏览器中打开预览。本 Skill **不直接操作实车硬件**，仅做知识查询与推理。

## 触发场景

当用户说出类似下面的话时触发本 skill：
- "P0301 是什么故障？"
- "帮我查下 P0420 的原因"
- "查询故障码 P0171 怎么修"
- "车报 U0100 通信丢失，什么情况？"
- "P0135 氧传感器加热器故障，怎么排查？"

## 知识库位置

- 知识库文件：`skills/Inquiry-dtc/data/dtc_knowledge_base.json`
- 结构：`dtcs` 数组，每条含 `code`、`name_en`、`name_zh`、`category`、`subcategory`、`severity`、`description`、`causes`、`steps`、`repairs`、`related`、`source` 字段。

## 执行流程

1. **提取故障码**：从用户话语中提取 DTC 码（形如 `P0301`、`C0035`、`B0100`、`U0100` 等，1 个字母 + 4 位数字，可能带后缀），大小写归一化为标准格式（如 `p0301` → `P0301`）。支持一次查询多个码。

2. **运行脚本生成 HTML**：在**当前工作目录**执行：
   ```bash
   python skills/Inquiry-dtc/scripts/make_dtc_report.py <CODE1> [CODE2 ...]
   ```
   脚本自动完成：查询知识库 → 未命中的码做族匹配并提示 → 生成 `dtc_<CODE>.html` → 打开浏览器预览。
   多码时生成一页报告（各码分区展示，相关码可跳转）。如需指定输出路径加 `-o`，不自动打开加 `--no-open`。

3. **核对结果**：若用户输入的码未命中知识库，脚本会输出族概述提示（如 `P03xx` 失火族），此时在回复中向用户说明该码不在知识库中，并建议核对故障码。

4. **补充推理**（可选）：当用户追问"可能是什么坏了"时，基于 `causes` 与 `steps` 归纳最可能的故障部件排序，并提醒相关码（`related`）供交叉诊断。

## 输出说明

- 生成文件：`dtc_<CODE>.html`，输出到**当前工作目录**（不是 skill 目录），便于用户在任意项目下使用。
- HTML 报告包含：故障码 + 中英文名称 + 严重程度徽章 + 分类 → 故障解释 → 可能诱因（编号）→ 排查步骤（编号）→ 维修建议（✓列表）→ 相关故障码（可点击跳转）+ 来源。
- 报告风格为暗色科技风，与 skill 一页摘要保持一致的视觉语言。

## 注意事项

- 本 Skill 为**纯推理查询类**，不连接 OBD、不读取实车数据、不执行任何维修动作，输出仅供参考，实际维修请以原厂维修手册与专业设备为准。
- 故障码统一按 `[A-Z][0-9]{4}` 归一化；制造商特有码（如 P1xxx/P2xxx 系列）可能与知识库条目不匹配，此时输出族匹配结果并说明局限。
- 当用户一次查询多个故障码时，脚本生成一页多码报告，Agent 最后补充故障码之间的关联分析（如多个码同源）。
- 报告中的"可能诱因"按概率排序（电气类 > 机械类 > 软件/通信类），便于快速定位。
